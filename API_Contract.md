🔐Authentication Specification
1.Source：
Generated by: WeChat Login API (Backend）
Timing of Generation: When a user calls `wx.login` and successfully exchanges the `js_code` for an `openid`, the backend generates a string (token) using JWT (JSON Web Token) or a custom encryption algorithm.
Include:The token internally encapsulates the user's OpenID and expiration time (ExpireTime).
2. Transmission
Retrieval: The frontend extracts the token from the JSON response of WeChat Login.
Storage: The frontend uses `wx.setStorageSync(‘token’, token)` to store the token locally on the device.
Inclusion: Except for the WeChat Login interface, all requests must include this token in the request header.
3.Format
Authorization: Bearer <Your_Token_Here>
4. Invalidation
Backend Validation: If the token has expired or been tampered with, the backend interceptor must intercept the request.
Response Status: Return code: 401 (Unauthorized).
Frontend Handling: Clear local storage and guide the user to retrigger the WeChat Login process.

Owner： Cici Liu
1. Business Flow
The lifecycle of a user after entering a mini-program is determined by the `registration_status`：
  Status 0 (New User): Call WechatLogin -> Redirect to the profile setup page (set profile picture/nickname).
  Status 1 (Partially Registered User): Information entered -> Redirect to LeetCode binding page (verify and bind ID).
  Status 2 (Fully Registered User): All permissions granted -> Go to the Home Page Leaderboard.

1. Business Logic
Privacy Settings: The guild is not searchable publicly; members must join using a specific invite_code.
Member Limit: Each guild is limited to 50 members.
Level Lock: If the total number of guild members is less than 5, all members’ levels will be automatically marked as “Recruited” during the daily settlement.

🏆Moldule_3 RankController Module
Owner： Dennis Du
1.Core Logic
📈1:2:3 Weighted Points Algorithm
The formula for calculating daily points (daily_points) is as follows: $$DailyPoints = (EasyAdded \times 1) + (MediumAdded \times 2) + (HardAdded \times 3)$$
Data source: The difference between the real-time number of ACs captured by LcEngineService and the previous day’s record in the database
🥇 Tie-breaker
When two members have the same daily_points:
First tiebreaker: The member with the higher daily_points (points for the day) is ranked higher.
Second tiebreaker: The member with the higher total_points (cumulative points) is ranked higher.
Third tiebreaker: If they are still tied, they are ranked in lexicographical order by openid.
📉 Rank_change
Up: Today's ranking < Yesterday's ranking (the lower the number, the higher the ranking).
Down: Today's ranking > Yesterday's ranking.
Keep: Ranking unchanged or first settlement.

3. Backend engine logic (DailySettleJob)
Execution Time: 22:00 daily (Cron: 0 0 22 * * ?)
Execution Process:
Full Scan: Iterate through all active users in the `users` table who have a bound `lc_id`.
Retrieve and Calculate: Call `LcEngineService` to retrieve the latest data, then calculate the daily E/M/H increments and `daily_points`.
Tiering:
Assign tiers based on percentile ranking within the team: Top 20%, Elite, Elite Plus, NPC, and “Done”.
Special Logic: Teams with fewer than 5 members or users with 0 points for the day are automatically classified as “Done”.
Snapshot Write: Write the results to the daily_logs table and update the total_solved column in the users table.
💾 Database relationship: daily_logs table

total_solved | INT | Snapshot of total solved questions after daily settlement |

3. Backend data processing logic
Data Aggregation:
The trend chart cannot query the `users` table directly; it must retrieve the top N records from the `daily_logs` table in reverse chronological order.
Zero-Filling Logic: If a user did not attempt any problems on March 25, there may be no record in `daily_logs`. The code must manually add `{“date”: “03-25”, “points”: 0}` before returning the data to the frontend; otherwise, the line chart will have a gap.
Poster Snapshot: GetSharePoster directly reads the latest `rank_tier` from the `daily_logs` table.
