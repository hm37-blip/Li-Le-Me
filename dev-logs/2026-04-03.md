# 力了么 开发日志 — 2026-04-03

## 一、微信账号登录持久化

### 原问题
同一个微信用户登录、加入战队后，退出登录再重新进入小程序，被要求从头注册。系统无法识别这是一个已注册的老用户。

### 根因
1. **`home.js` 的 `handleLogout()` 调用了 `wx.clearStorageSync()`**，把 `device_id` 一起清掉了。再次登录时生成了全新的 `device_id` → 后端计算出不同的 mock openid → 认为是新用户 → 走注册流程。
2. **`app.js` 的 `onLaunch` 没有自动路由**。即使本地缓存了 `openid` 和 `token`，用户仍然停留在登录页，必须手动点击"微信登录"。
3. **后端 `/api/wechat/login` 对老用户不返回 `user_info`**，导致即使识别到老用户，前端也拿不到昵称、LC 用户名等信息。

### 修改
| 文件 | 改动 |
|---|---|
| `miniprogram/pages/home/home.js` | `handleLogout` 在 `clearStorageSync` 前保存 `device_id`，清除后恢复 |
| `miniprogram/app.js` | `onLaunch` 检测到缓存的 `openid`+`token` 后，调用 `GET /api/user/status` 验证用户状态并自动跳转到对应页面 |
| `WechatLoginController.java` | 对已存在用户（`!isNew`）在响应中追加 `user_info` 字段（nickname, leetcode_username, avatar_file_id, squad_id） |
| `LeetCodeBindController.java` | 新增 `GET /api/user/status` 接口，通过 token 查用户，返回 `registration_status` 和完整 `user_info` |
| `UserRepository.java` | 新增 `findByToken(String token)` 查询方法 |

## 四、前端数据流修复

### 原问题
首页 LeetCode 用户名显示"未绑定"，战队成员显示"暂无成员"，但实际数据库中数据正确。

### 根因
`globalData.userInfo` 在注册流程的多个页面中被零散地赋值和覆写：

```
bindlc.js → globalData.userInfo = { leetcode_username: 'xxx' }
                                        ↓
profile.js → globalData.userInfo = { user_nickname, avatar_file_id, squad_name }
             ↑ 直接覆写，leetcode_username 丢失
```

首页从 `globalData.userInfo` 读取数据，拿到的是不完整的对象。

### 修改
| 文件 | 改动 |
|---|---|
| `miniprogram/pages/profile/profile.js` | 加入战队成功后，用 spread 运算符 `...(app.globalData.userInfo \|\| {})` 保留已有字段，不再覆写 |
| `miniprogram/pages/home/home.js` | `onShow` 不再依赖 `globalData` 碎片数据，改为直接调 `GET /api/user/status` 从后端获取完整用户信息 |
| `LeetCodeBindController.java` | `/api/user/status` 接口追加返回 `squad_name`（通过 `SquadRepository` 查询），注入 `SquadRepository` 依赖 |
