# Li-Le-Me Dev Log — 2026-04-03

## 1. WeChat Login Persistence

### Problem
After a registered user logged out and reopened the mini-program, they were taken through the full registration flow again — the system failed to recognize them as an existing user.

### Root Cause
1. **`home.js` `handleLogout()` called `wx.clearStorageSync()`**, which wiped `device_id` along with everything else. On next login, a new `device_id` was generated → the backend derived a different mock openid → treated the user as new → triggered registration.
2. **`app.js` `onLaunch` had no auto-routing logic.** Even with a cached `openid` and `token`, the user still landed on the login page and had to tap "WeChat Login" manually.
3. **The backend `/api/wechat/login` did not return `user_info` for existing users**, so even when the user was correctly identified, the frontend had no access to their nickname, LC username, etc.

### Changes

| File | Change |
|---|---|
| `miniprogram/pages/home/home.js` | `handleLogout` saves `device_id` before `clearStorageSync`, then restores it after |
| `miniprogram/app.js` | `onLaunch` checks for cached `openid` + `token`, calls `GET /api/user/status` to verify state, and auto-routes to the appropriate page |
| `WechatLoginController.java` | For existing users (`!isNew`), appends `user_info` to the response (nickname, leetcode_username, avatar_file_id, squad_id) |
| `LeetCodeBindController.java` | New `GET /api/user/status` endpoint: looks up user by token, returns `registration_status` and full `user_info` |
| `UserRepository.java` | New `findByToken(String token)` query method |

## 4. Frontend Data Flow Fix

### Problem
The home page showed "Not bound" for the LeetCode username and "No members" for the squad list, despite the database containing correct data.

### Root Cause
`globalData.userInfo` was being assigned and overwritten in a fragmented, scattered way across multiple registration pages:

```
bindlc.js → globalData.userInfo = { leetcode_username: 'xxx' }
                                        ↓
profile.js → globalData.userInfo = { user_nickname, avatar_file_id, squad_name }
             ↑ direct overwrite — leetcode_username is lost
```

The home page read from `globalData.userInfo` and received an incomplete object.

### Changes

| File | Change |
|---|---|
| `miniprogram/pages/profile/profile.js` | After joining a squad, uses spread `...(app.globalData.userInfo \|\| {})` to merge fields rather than overwrite |
| `miniprogram/pages/home/home.js` | `onShow` no longer relies on fragmented `globalData`; instead calls `GET /api/user/status` directly to fetch the full user object from the backend |
| `LeetCodeBindController.java` | `/api/user/status` now also returns `squad_name` (queried via `SquadRepository`); added `SquadRepository` dependency injection |
